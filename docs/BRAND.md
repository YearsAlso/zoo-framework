# 品牌与视觉规范 / Brand & Visual Guidelines

> 本文件是视觉资产的**单一真源**。改动标识、配色或图表前请先读这里；
> 贡献者与 AI agent 在生成图片、文档或界面素材时 MUST 遵守本文规则。

---

## 1. 为什么标识不能用插画

原标识是一只写实卡通麻雀。它在三个方面与项目定位冲突，因此被替换为几何标识：

| 问题 | 说明 |
|---|---|
| **与受众冲突** | 受众是开发者与 AI agent 平台。"写实卡通动物"读作个人兴趣项目或教育工具，而 Python+Rust 品类的视觉共识是极简几何（`orjson`、`msgspec` 无标识）。 |
| **隐喻自相矛盾** | 项目名为 zoo，但麻雀并不生活在动物园里——这个不一致本身就是"包装未想清楚"的可见证据。 |
| **不可缩放** | 写实插画在 favicon（16px）与列表缩略图下不可辨。实测：原标识在 16px 时细节完全糊合。 |

**隐喻保留在命名中，不再由插画承担。** 标识改用几何构造表达语义。

## 2. 标识构造

```
环（stroke 7）  = 生命周期 / 容器作用域（对应 Master 与 ScopedContainer）
三条不等高的条   = 同一调度器下负载不同的 Worker（在飞、活跃、空闲）
中间条用强调色   = 当前被观测的那个任务
```

几何刻意与本项目的**基准柱状图同形**——图表、标识、文档共用同一套视觉语法。

| 文件 | 用途 | 说明 |
|---|---|---|
| `assets/logo.svg` | README 首屏、封面 | 图形 + 文字（横排锁合） |
| `assets/logo-dark.svg` | 同上，深色背景 | 深色模式变体 |
| `assets/mark.svg` | 文档站页眉、嵌入图 | 仅图形 |
| `assets/mark-dark.svg` | 同上，深色背景 | |
| `assets/wordmark.svg` | 仅需文字时 | `zoo framework` |
| `assets/wordmark-dark.svg` | 同上，深色背景 | |
| `assets/favicon.svg` | favicon、列表缩略图 | **小尺寸专用变体**，见下 |
| `assets/logo.png` | 需要位图的场合 | 由 `logo.svg` 渲染，720px 宽 |
| `assets/mark.png` | 头像、PyPI 图标、幻灯片 | 512×512，透明底 |
| `assets/favicon.png` | apple-touch-icon、社交嵌入 | 180×180 |

### ⚠️ 小尺寸必须用 `favicon.svg`，不要用 `mark.svg`

实测对比（16 / 20 / 24 / 32px）：`mark.svg` 的细描边环在小尺寸下糊成一团；
`favicon.svg` 改用「**实底 + 挖空条**」，边缘对比度显著更高，在 16px 与深色背景下都成立。

**规则**：目标显示尺寸 **< 40px 时 MUST 使用 `favicon.svg`**；≥ 40px 用 `mark.svg`。

### 生成规则

- 新增的图形资产 **MUST 是 SVG**；PNG 只作为由 SVG 渲染出的下游产物存在
- PNG 渲染：`sharp`（或任意 SVG 渲染器），`logo.png` 目标宽度 720px
- 位图产物 MUST 可由对应 SVG **重新生成**，不得手工编辑

## 3. 色彩

```css
/* 主色 · 深靛蓝 —— 承担约 80% 的视觉重量 */
--ink-900: #1A2530;   /* 文字主色 / 深底 */
--ink-800: #223344;   /* 标识主色 */
--ink-700: #2C4152;
--ink-600: #3A5468;

/* 强调色 · 青绿 —— 只用于强调与交互态，MUST NOT 大面积填充 */
--teal-600: #1177aa;
--teal-500: #1E9DB0;
--teal-400: #33aa99;  /* 标识强调色 */
--teal-300: #7FD6C4;  /* 深底上的强调 */

/* 中性阶 */
--n-50:  #F7F9FA;  --n-100: #EDF1F4;  --n-200: #D8DFE4;
--n-300: #B9C4CC;  --n-500: #6B7C8A;  --n-700: #3A4650;

/* 深色模式 */
背景 #141A1F · 正文 #E7EDF1 · 次要文字 #93A3AF · 强调 #7FD6C4
```

**三条硬约束**

1. 青绿 MUST NOT 用于大面积填充——会让框架读起来像消费级 App
2. 深靛蓝承担 80% 的视觉重量（标题、深色区块、图表的框架线）
3. **红色只用于"我们输的那一档"**，且 MUST 附文字标注（见 §5）

## 4. 字体

| 用途 | 字族 |
|---|---|
| 正文 / 文档 | 系统栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif` |
| 代码 | `ui-monospace, SFMono-Regular, "SF Mono", "Cascadia Code", Consolas, monospace` |

**中文字族 MUST 显式声明**（`PingFang SC` / `Microsoft YaHei` / `Noto Sans CJK SC`）——
本仓库文档中英双语，不声明会导致不同平台字形跳变。

字号阶梯：H1 32 / H2 24 / H3 19 / 正文 16 / 图注 14 / 代码 14（行高 1.6）。

**图内字号 MUST NOT 小于 14px。** 见 §5。

## 5. 图表规范

| 规则 | 理由 |
|---|---|
| 白底、无边框、无阴影 | 现有图已符合 |
| 深靛蓝画结构，青绿画"流"（数据 / 事件 / 调度方向） | 与色彩系统一致 |
| 单图内语义色 ≤ 4 种 | 可读性 |
| **红色只标注"我们输的那一档"，且必附文字** | 与项目"如实报告在哪一段不适用"的立场一致；这是差异化的视觉资产 |
| 相对倍数图（×）优先于绝对数值图（ms/µs） | 跨平台可比性 |
| 每张图下 MUST 有"读法"说明 | 例：本图测的是调度开销，采集于 Windows 11 / Python 3.13 |
| **图内字号 ≥ 14px** | `architecture.en.png` 是 1462×1596，在 GitHub 正文宽度（约 860px）下被缩到 59%——原图 12px 的字缩后只剩 7px，不可读 |

**深色模式**：现有图均为白底 PNG，在 GitHub 深色模式下显示为**白色矩形**。
新增图 MUST 提供 SVG；已存在的白底图 SHOULD 逐步改为 SVG。

## 6. 禁止项

| ❌ | 原因 |
|---|---|
| 拟人化 / 卡通动物插画 | 与工程定位冲突 |
| 大面积渐变、玻璃拟态、外发光 | 读作消费级产品 |
| 用 emoji 充当架构图元素 | 图内 MUST NOT 使用 emoji |
| 红色用于正面数据 | 红色默认读作"错误" |
| 仅有白底 PNG、无深色版 | 深色模式下是白色矩形 |
| 图内字号 < 14px | 缩放后不可读 |
| 手工编辑 PNG 位图 | 必须可从 SVG 重新生成 |
