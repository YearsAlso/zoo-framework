# 路线图

本页列出**使用者能感知**的能力方向，按 Now / Next / Later 组织。

**没有日期承诺。** 项目由一人维护，给出日期只会制造无法兑现的预期——
上一版本页把 `v1.0` 承诺在 `2024.06`，而当时与现在的实际版本是 `0.10.x`。
与其继续给日期，不如给出**状态**与**完成标准**：让你判断进度，
而不是让你相信一个我们无法保证的时间点。

> **内部债务项**（CI、合规、重构）不在本页，见
> [`docs/MAINTAINER_BACKLOG.md`](maintainer-backlog.md)。

---

## Now（进行中）

### 让首次运行就有成功时刻

**你要解决的问题**：`zfc --create` 产出的项目**没有任何 Worker**，
跑起来看不到业务输出，只有框架自身的调度日志。

| 项 | 内容 |
|---|---|
| 状态 | 未开始（issue #110 / #111） |
| 完成标准 | `zfc --create myapp && cd myapp && python src/main.py` 在 5 秒内打印出属于使用者的输出；默认日志级别下框架日志不再淹没它 |

### 降低 Python 版本门槛

**你要解决的问题**：当前 `requires-python = ">=3.13"` 把大量仍在 3.10–3.12 的环境排除在外，
也使本框架难以作为依赖被其它项目引入。

| 项 | 内容 |
|---|---|
| 状态 | 调研中（issue #124） |
| 完成标准 | 下界降到 3.11 或更低，CI 在下界版本上全绿，且全部文档中的版本声明一致 |

### 文档只维护一份、且内容不假

**你要解决的问题**：仓库里曾有**两个并行的文档站**，且各自的 API 示例中有大量不存在的接口
（如 `EventChannelManager`、`StateMachineManager.create_state_machine`）。

| 项 | 内容 |
|---|---|
| 状态 | 站点收敛已完成；API 引用校验已接入 CI；内容补齐进行中 |
| 完成标准 | 用户文档站唯一；文档中的每一条 API 引用都能被 CI 校验；API 参考覆盖全部公开导出面 |

## Next（已确认要做）

### 可插拔的调度节拍

**当前限制**：只有固定 `delay_time` 轮询，**不支持 cron 表达式**。
需要 cron 的用户目前应当使用 APScheduler。

| 项 | 内容 |
|---|---|
| 完成标准 | 配置层面可表达「每天 09:00」「每 5 分钟」这类节拍，且与现有 `delay_time` 语义不冲突 |

### 可观测性导出

**你要解决的问题**：目前只能读框架自己的日志。接到自己的可观测性栈（OpenTelemetry / Prometheus）
需要手写胶水。

| 项 | 内容 |
|---|---|
| 完成标准 | 提供一条官方的指标导出路径（例如 OpenTelemetry），文档给出可直接运行的示例 |

### 与 Web 框架共存的官方示例

**你要解决的问题**：FastAPI / Django 的进程内后台任务缺少可靠的内建方案
（`BackgroundTasks` 无状态、重启即丢），而没有现成示例说明怎么用本框架替代。

| 项 | 内容 |
|---|---|
| 完成标准 | 至少一个可运行的 FastAPI 集成示例，演示「重启后状态恢复」这一 `BackgroundTasks` 做不到的事 |

### 原生执行（Rust）交付给使用者

**当前限制**：`native/` 已通过阶段性验收（粗粒度 CPU 任务实测 **2.83x–9.71x**），
但**无 CI、未启用 abi3、未发布到 PyPI**——**没有任何使用者能安装到它**。

| 项 | 内容 |
|---|---|
| 状态 | issue #129 |
| 完成标准 | `pip install zoo-framework[native]` 可用；wheel 用 abi3 覆盖多个 Python 版本；CI 在三平台构建 |

## Later（在考虑，尚未承诺）

以下方向已进入视野，但**没有排期**，也可能不做。写在这里是为了让你知道我们在想什么。

| 方向 | 说明 |
|---|---|
| **健康监控指标链路** | `get_health_report()` 当前恒返回 `execute_count: 0`（指标链路未接通）。要么接通，要么在 API 上明确标为不可用 |
| **跨平台行为一致性** | 让 Windows / macOS / Linux 上的调度与持久化语义有可复现的验证，而不只是「应该一致」 |
| **多进程执行** | 当前是显式未实现（模式常量是占位，请求会抛错）。若要做，需要先想清楚与 Celery 的边界 |
| **原生任务 SDK** | 让第三方能发布自己的原生任务（见 issue #139） |

---

## 明确不做的

写在这里以节省你的评估时间：

| 不做 | 原因 |
|---|---|
| 跨机器分布式调度 | 这是 Celery 的领域。选它，不要选我们 |
| 图形化编排面板 | Dagster / Prefect / Airflow 已经做得很好 |
| 自带 Web 控制台 | 同上 |

## 怎样判断进度是真的

本页刻意不写日期，但每一项都有**可验证的完成标准**。除此之外：

- **版本与变更**：以 [`CHANGELOG.md`](https://github.com/YearsAlso/zoo-framework/blob/dev/CHANGELOG.md) 为准
- **性能主张**：以 [`zoo-bench`](https://yearsalso.github.io/zoo-bench/) 的原始数据为准（含我们输在哪一档）
- **已发布的版本**：以 [PyPI](https://pypi.org/project/zoo-framework/) 为准

**若本页与上述任一来源冲突，以那些来源为准。**
