# 路线图

这一页只写**你能因此多做到什么**。维护者自己的工作（CI、合规材料、重构、发版流程、
审计整改）不在此列，见 [维护者待办台账](maintainer-backlog.md)。

**怎么读**：每条三行——

- **能做什么了**：以使用者视角陈述能力，不是实现方式；
- **影响谁**：什么场景下的人会在意；
- **怎么知道做完了**：可观测的完成判据（能验证，不是"覆盖率到 80%"这类过程指标）。

分三档：**Now**（正在推进，0.10.x 版本线）／**Next**（已立项，有对应 issue）／
**Later**（在考虑，方向待评审，尚未立项）。

---

## Now —— 正在推进（0.10.x 版本线）

### 事件管道：推模型 + 批量投递（0.10.2-beta 起可用）

- **能做什么了**：通道空闲时不再空转轮询、同一响应器的多个事件成组投递；配置键
  `event:pushModelEnabled`（默认关）、`event:batchMaxSize`（默认 64）可控，关闭即回到旧行为。
- **影响谁**：事件量大、或在意空载 CPU 占比的后台服务。
- **怎么知道做完了**：开关在真实负载下验证事件去向恰好其一（投递／回队／死信），
  并把两个开关的默认值是否转正写进 CHANGELOG。

### 原生任务执行（0.10.3-beta 起可用，扩展包待可直接安装）

- **能做什么了**：计算密集任务可交给编译型执行体（配置键 `native:*`，默认关）；
  未安装扩展时现有功能零变化，显式请求原生能力会明确报错而非静默回退。
- **影响谁**：已能接受额外构建步骤、且被 CPU 密集任务卡住的使用者。
- **怎么知道做完了**：扩展包可从 PyPI 直接装到对应平台 wheel（目前需本地构建），
  且安装失败有清晰提示。

### 自适应调度（0.10.2-beta 起可用）

- **能做什么了**：`DualArmWorker` 用在线统计在原生／Python 两臂之间自动选择执行体，
  不必自己写开关与回退逻辑；统计可持久化（`adaptive:statsPath`）。
- **影响谁**：同一批任务里负载波动大、手动调参不划算的场景。
- **怎么知道做完了**：`adaptive:enabled` 是否转默认开，由实测数据决定并记录在 CHANGELOG。

## Next —— 已立项（有 issue 编号，做完即关闭对应 issue）

### 原生任务 SDK（[#139](https://github.com/YearsAlso/zoo-framework/issues/139)）

- **能做什么了**：把自己的任务注册表按公开 SDK 接入原生执行，不必改框架内部代码。
- **影响谁**：想把自有重计算任务接进原生路径的插件作者与集成方。
- **怎么知道做完了**：文档站出现 SDK 章节与最小可跑示例，且第三方按该文档接入无需改框架。

### 与上游生态的真实集成（[#138](https://github.com/YearsAlso/zoo-framework/issues/138)）

- **能做什么了**：在 2–3 个你已在用的上游项目的文档里，看到 zoo 的可用集成方式。
- **影响谁**：从那些上游找方案进来的人。
- **怎么知道做完了**：至少一条上游文档（或官方示例仓）链接到本框架，并给出可复现的集成步骤。

### 降低 Python 版本门槛（[#124](https://github.com/YearsAlso/zoo-framework/issues/124)）

- **能做什么了**：在 3.11／3.12 等现有生产环境里安装使用，而不是被 `>=3.13` 挡在门外。
- **影响谁**：受 `requires-python` 限制、短期内无法升级解释器的团队。
- **怎么知道做完了**：`pyproject.toml` 门槛下调且最低版本在 CI 三平台全绿，
  README、`docs/VERSION_POLICY.md` 与安装指南同步更新。

## Later —— 在考虑（方向待评审，尚未立项）

### 可插拔调度节拍（cron 式表达式）

- **能做什么了**：用 cron 表达式或自定义节拍替代固定的 `delay_time` 轮询。
- **影响谁**：定时报表、日终同步、按业务时点触发的任务。
- **怎么知道做完了**：新增节拍配置键并在文档站有专章；语义变化进 `docs/MIGRATION.md`。

### 可观测性导出（OpenTelemetry）

- **能做什么了**：把调度与事件指标接到你自己的可观测性栈（OTLP／Prometheus），不用改框架。
- **影响谁**：已有统一监控体系、要求指标入湖的团队。
- **怎么知道做完了**：可选依赖的 exporter + 指南页 + 一个可跑通的最小示例。

### 健康监控指标链路接通

- **能做什么了**：`get_health_report()` 返回真实的执行计数与健康判据，README 限制表里
  那条 ⚠️（"指标链路未接通，恒为 0"）消失。
- **影响谁**：依赖 `Master` 上报健康状况做值守与告警的团队。
- **怎么知道做完了**：`execute_count` 在真实调度下可复现为非零，README 特性表该行
  由 ⚠️ 改为 ✅。

### Web 框架生命周期集成（FastAPI／Django）

- **能做什么了**：把 Master 的启动／关闭挂进 Web 框架的生命周期钩子，不必自己管线程与退出。
- **影响谁**：以 Web 服务形态承载后台 Worker 的团队。
- **怎么知道做完了**：两个框架各一篇可跑示例，且在 CI 中能够执行通过。

### 跨平台行为一致性

- **能做什么了**：同样的调度与持久化语义在 Windows／macOS／Linux 表现一致、结果可复现。
- **影响谁**：在非 Linux 环境部署或需要多平台一致行为的使用者。
- **怎么知道做完了**：三平台 CI 稳定全绿，且文档写明各平台已知差异基线（而非靠使用者踩坑）。
