# Skill: bug-investigation-memory — Bug 排查记忆生成

## 触发时机

bugfix workflow 阶段 2.5（定位 → 同类排查），在 code-indexer 输出根因分析后调用。

## 输入
- code-indexer 的根因分析输出（文件:行号、调用链、根因类型）
- 受影响的代码路径列表

## 执行流程

### Step 1: 读取模板
读取 `docs/template/bug-investigation-memory-template.md`，确认模板结构（模板缺失时按 doc-template "无模板处理"提示创建，或参考本 skill 的"生成内容"清单）。

### Step 2: 读取已有记忆
读取 `docs/memory/bug-investigation-memory.md`，若存在则获取最后一条记录的序号作为基数；若不存在则创建。

### Step 3: 同类排查
基于根因分析，在代码库中搜索以下三类模式：

| 排查维度 | 搜索策略 | 目标 |
|---------|---------|------|
| **同模块** | Grep 根因文件所在目录的同类代码 | 同一模块内是否存在相同模式 |
| **同模式** | Grep 根因代码模式（如相同的装饰器用法、相同的属性读取、同样的 except 块） | 是否存在相同的错误模式 |
| **同类型** | Grep 根因类型（如 falsy 配置值误判、`is_loop` 属性误读、引用未重置的全局状态）在项目中的其他实例 | 是否存在同类型但不同位置的问题 |

搜索用 `Grep`（结构/文本），必要时 `Glob` 缩窄目录范围。

> 本项目高频根因类型参考：`is_loop` 被当属性读恒真、falsy 配置值被当缺失、params 模块过早导入冻结默认值、`@cage`/`WorkerRegistry` 全局状态跨用例泄漏、thread 模式 `WorkerResult` 被丢弃。

### Step 4: 生成排查记忆
按模板结构生成排查记录，包含：
1. **元信息** — 排查日期、根因文件:行号、根因类型标签
2. **问题概要** — 一句话描述根因
3. **根因分析** — 复现路径、调用链、关键代码、证据
4. **受影响文件** — 变更清单表格
5. **同类排查结果** — 逐文件/模块排查结果表格
6. **同类问题统计** — 排查范围、发现数、需修复数
7. **修复建议** — 修复策略、涉及文件、优先级
8. **预防措施** — 规范补充、测试补充、审查清单补充

### Step 5: 写入记忆
将生成的排查记录追加到 `docs/memory/bug-investigation-memory.md`：
- 文件存在 → 追加新记录（递增序号）
- 文件不存在 → 创建文件，写入文件头信息后追加

### Step 6: 输出同类排查结果摘要
将同类排查结果摘要输出给主对话，供下一阶段（最小修复）参考：
- 是否有需修复的同类问题
- 同类问题清单（文件:行号 + 修复建议）
- 本次修复是否应覆盖同类问题

## 输出
- `docs/memory/bug-investigation-memory.md` — 追加后的排查记忆文档
- 同类排查结果摘要 — 供 software-engineer 修复阶段参考

## 工作约束
- 只查不改：排查记忆只记录发现，不修改代码
- 排查范围覆盖上游调用者与下游被调用者，不限于根因文件本身
- 疑似但不确认的同类问题在说明中标注"疑似"，不写入"需修复"统计
- 排查记录不可覆盖或删除，仅追加
