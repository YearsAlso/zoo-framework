# 金字塔原则回答规则 — Pyramid Answer

## 原则

**回答一律采用金字塔结构：先论点，再论据，逐级展开。**读者在前 3 行内必须能看到核心结论，正文再逐层支撑结论。

与「通俗总结规则」配合使用：正文按金字塔展开，末尾仍附通俗总结。

## 要求

| 项 | 标准 |
|----|------|
| 开头 | 前 1-3 行直接给出结论 / 观点 / 推荐方案，不铺垫、不绕弯 |
| 结构 | 结论 → 2-5 个关键论据 → 每个论据下的证据（代码、文件、数据） |
| 层级 | 每一层只展开上一层的观点；子观点用小标题或加粗引导句单独成段 |
| 排序 | 最重要的论据放最前；同级内容按重要性递减 |
| 呼应 | 结论必须有论据支撑，论据必须能回扣结论 |

## 禁止行为

- ❌ 先大段叙述背景 / 过程 / 调研路径，结论压在最后
- ❌ 细节平铺堆砌，读者读完仍不知道核心观点是什么
- ❌ 同一段落混排多个层级的内容（结论与细节纠缠）
- ❌ 只给结论不论据，或论据与结论无关

## 例外

以下场景可调整结构：

- 探索性排查：结论尚不可知时，先给当前判断与排查路径，得到阶段性结论后立即前置
- 用户明确要求先看推理过程再看结论
- 一两句话能答完的简单问题：直接回答，无需刻意搭金字塔
