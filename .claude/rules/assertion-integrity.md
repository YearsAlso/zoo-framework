# 断言有效性规则 — Assertion Integrity

## 原则

**测试断言必须证明「被测代码做了什么」，而不是「某个对象现在的状态是什么」。**

对**可变对象**按引用捕获的断言（`mock.assert_called_with(obj)` / `call.args[0].field == V` / pytest 自定义捕获列表）在**验证期**才对已被就地改写的对象求值 —— 断言恒真或恒假，**与实现是否正确无关**。

## 规则说明

本框架的 Worker / 状态机 / 事件管道普遍**就地改写传入对象**（如 `node.retry_count += 1`、`worker.status = "warning"`、`state.current = NEW`），而 `unittest.mock` 的 `call_args` / `assert_called_with` 记录的是**实参引用**，验证时读到的是对象的**最终内存态**。两者相遇 ⇒ 无法证明「该次调用携带的值」。

**必须**改用**调用时快照**：在 `side_effect` 内记录调用当时的字段值（或 `copy.copy` 浅拷贝），再对整条序列断言。

| 场景 | ❌ 无效写法 | ✅ 有效写法 |
|---|---|---|
| 断言「某状态从未被写入」 | `mock.update.assert_called_with(obj)` 后检查 `obj.status != A`（事后态） | `side_effect` 记录每次调用的 `obj.status` → `assert A not in writes` |
| 断言「某状态被写入一次」 | `mock.update.call_count == 1`（次数对但携带值不可证） | `assert writes == [A]`（同时证明**次数与内容**） |
| 断言「调用携带两个字段」 | 两次独立字段检查 | `side_effect` 记录 `(status, topic)` 元组 → 整序列比对 |
| 断言集合不含某元素 | `assert x not in collection` | 先 `assert collection` 再断言 |
| 断言某动作「已发生」 | 对可能为空的捕获列表用 `all(...)` | 先 `assert len(...) == 1` 再断言 |
| 断言「未写入旧值」 | `assert (key, 旧值) not in upserts` | 断言「已尝试写入**目标新值**」的次数与内容 |
| 断言「某键已复位」 | 无前置地对键断言已清除 | 先断言键**曾被置位**（`assert key in held_events`）再断言已清除 |

## 禁止行为

- ❌ 对**可变对象**用引用捕获式断言（`assert_called_with(可变对象)` / 验证期读 `obj.可变字段`）
- ❌ 把「调用次数」当作「落库/投递内容」的证据
- ❌ 对可能为空的集合做否定式断言而不先断言非空
- ❌ 断言「未写入某值」而不证明「确实尝试过写入」—— 否则「没做」与「做对了」不可区分
- ❌ 用**空断言**充当证据（如对未被置位的状态断言「已复位」，此时该断言恒真）
- ❌ 依赖 `@cage` 单例 / `WorkerRegistry` 全局状态的测试不做**测试间重置**——前一个用例的残留会让后续断言在"错误实现"下依旧绿

## 例外（引用捕获写法安全的情形）

- 依赖字段是**终态不可逆**（如置为 `CLOSED` 后不会再被改回）→ 只存在「假失败」方向，无假通过路径
- 实参是**不可变值**（`str` / `int` / `bytes` / frozen dataclass / `NamedTuple`）→ mock 记录的值即调用时的值
- 对象在**构造后不再被改写**（如事件构造后立即投递通道）
- **反例特征化测试**（故意保留无效写法以记录陷阱本身）→ 须在 docstring 中标明用意，否则后人会当反例仿写

## 判别方法与验收

**判别**：问「若把实现改错（把断言要拦的行为做出来），这条断言会红吗？」—— 若不会，它就没有牙齿。

**唯一可靠的验收方式**：**临时注入违规实现，确认断言变红，再按哈希逐字节还原**（还原后须核对源文件与打桩前一致）。只读一遍测试代码不足以判定其有牙齿。注入/还原遵守 `.claude/workflows/bugfix.md`「审查与验证的串行纪律」：带 `VIOLATION-` 标记、串行执行、md5 留痕。

## 触发场景

编写单元测试断言时；审查 `tests/**` 时。unit-tester 编写测试前按 `test-design` skill 引用本规则；reviewer 审查测试代码时按本规则检查。

## 反例特征（通用化总结）

「看起来在测、其实永远通过」的三大类断言（任何就地改写 + 引用捕获的项目都会出现）：

- **空断言**：对未置位（无前置状态）的键/标志断言「已清除」/「已复位」—— 缺前置断言时恒真
- **引用捕获陷阱**：`assert_called_with(实体)` 在实体已被就地改写后与实现无关
- **恒真断言**：`all(...)` 作用于空列表、`x not in []`、对空 mock 记录序列的一切否定式检查

**破坏力**：这类断言可能恰好守着项目最关键的不变量（如持久化原子性、事件不丢、状态不回退）—— 违规实现在断言全绿的情况下照常合入。
