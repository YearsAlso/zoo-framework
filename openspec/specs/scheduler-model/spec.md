# scheduler-model Specification

## Purpose

定义调度模型的显式契约与选择语义：每个模型 MUST 声明其并发原语、**支持的时间语义**、背压策略、停机语义、支持的 Worker 类别与可观测指标，而模型无关的正确性逻辑 MUST 由共享实现承担。该能力使"运行策略"真正承载模型差异，并让不支持的请求被明确拒绝而非静默降级。

## Requirements

### Requirement: 调度模型 MUST 以显式接口声明其契约

每个调度模型 SHALL 通过显式接口声明以下六项：并发原语、**支持的时间语义**、背压策略、停机语义、支持的 Worker 类别、可观测指标。该契约 MUST 可被程序化查询，MUST NOT 仅存在于文档或类名之中。

"支持的时间语义"声明的是**该模型能够调度哪些时间语义的集合**，MUST NOT 被理解为把整个进程钉在某一种语义上。周期与相位由 Worker **逐个声明**（见 `execution-time`），因此同一模型下 MUST 可以同时调度周期驱动与事件驱动的 Worker——设备场景里周期控制回路与事件驱动报警处理器共存正是如此。

#### Scenario: 模型契约可被程序化查询
- **WHEN** 取得任一调度模型并查询其契约
- **THEN** 并发原语、支持的时间语义、背压策略、停机语义、支持的 Worker 类别与可观测指标六项均可获得且非空

#### Scenario: 声明的并发原语与执行位置一致
- **WHEN** 按某模型声明的并发原语执行一个 Worker
- **THEN** 该 Worker 的执行位置与该声明一致，而非静默使用另一种原语

#### Scenario: 时间语义不被模型级别钉死
- **WHEN** 同一模型下同时调度一个声明了周期的 Worker 与一个未声明周期的 Worker
- **THEN** 两者都被调度，前者按周期序列触发、后者每轮触发

### Requirement: 模型无关的正确性逻辑 MUST 由共享实现承担

单一结算收口、超时观测与熔断、停机资源回收、运行期注册生效、**以及"某个 Worker 此刻是否到点"的周期排期判断**这五类与模型无关的正确性逻辑 SHALL 由共享实现承担，新增调度模型 MUST NOT 重新实现它们。

周期排期与并发原语无关——它只依赖 Worker 声明的周期/相位与单调时钟。若由各模型自行实现，绝对序列、跳过语义与抖动采集会被实现多遍且必然出现分歧。

#### Scenario: 新模型不重复实现结算收口
- **WHEN** 新增一个调度模型并执行一批 Worker
- **THEN** 每个 Worker 的执行状态仍由单一收口维护，同一 Worker 不被重复结算

#### Scenario: 新模型继承停机回收语义
- **WHEN** 对使用新模型的调度器发起停机
- **THEN** 在飞 Worker 被回收、资源被释放，语义与既有模型一致

#### Scenario: 新模型继承运行期注册语义
- **WHEN** 向使用新模型的调度器运行期新增 Worker
- **THEN** 该 Worker 进入调度并被执行

#### Scenario: 新模型继承周期排期语义
- **WHEN** 一个声明了周期的 Worker 由新增的调度模型调度
- **THEN** 它按周期序列触发（含跳过语义），而非每轮都触发

#### Scenario: 新模型继承超时观测与熔断
- **WHEN** 使用新模型的 Worker 执行超过其期限
- **THEN** 该次超期被记录、该 Worker 被标记不健康且不再被重派

### Requirement: 模型选择 MUST 显式且不做降级

选择调度模型时，若模型不支持请求的 Worker 类别或时间语义，系统 MUST 明确拒绝并指明不兼容之处，MUST NOT 降级到其他模型，MUST NOT 静默忽略该 Worker。

#### Scenario: 不兼容的请求被明确拒绝
- **WHEN** 请求一个模型未声明的 Worker 类别或时间语义
- **THEN** 该请求被拒绝并指明不兼容之处，而非静默改用其他方式执行

#### Scenario: 拒绝信息列出可选模型
- **WHEN** 模型选择被拒绝
- **THEN** 错误信息列出当前可选模型的名称

### Requirement: 模型 MUST 暴露运行期可观测指标

每个模型 SHALL 提供至少四项可在运行期查询的指标：在飞执行数、累计完成数、超期熔断数、以及实际触发抖动。指标 MUST NOT 只在停机时可得。对于事件驱动的模型，抖动指标 SHALL 显式标明"不适用"，MUST NOT 以 0 代替。

#### Scenario: 运行期可查询在飞与完成数
- **WHEN** 在 Worker 执行过程中查询模型指标
- **THEN** 在飞执行数与累计完成数可被获得，且与实际情况一致

#### Scenario: 超期熔断被计数
- **WHEN** 某次执行超过其期限并被熔断
- **THEN** 超期熔断数增加

#### Scenario: 周期模型的抖动指标有值
- **WHEN** 查询周期驱动模型的抖动指标
- **THEN** 返回可用的抖动数值，而非"不适用"

#### Scenario: 事件驱动模型显式标明抖动不适用
- **WHEN** 查询事件驱动模型的抖动指标
- **THEN** 返回"不适用"的显式标注，而非 0

### Requirement: 策略解析结果 MUST 按 Worker 缓存且 MUST NOT 改变三段解析语义

调度内核 SHALL 按「Worker 名 + 属性」缓存周期 / 相位 / 超时的三段解析结果（自报 → 按 Worker 名覆盖 → 全局默认），MUST NOT 在每轮调度中对同一 Worker 重复查询参数。缓存 MUST NOT 改变任何一段的取值语义：falsy 的已解析值（`0` / `False` / `""` / `None`）MUST 作为**有效结果**命中，MUST NOT 被判定为未命中而重新解析或穿透到下一段。缓存 MUST 在以下三个入口失效：调度列表整体替换、同名 Worker 重新注册、内核复位（停机清理）。

#### Scenario: 同一 Worker 的解析只查询一次参数
- **WHEN** 对同一 Worker 连续多轮解析周期/相位/超时，且期间未发生列表替换或重注册
- **THEN** 对 `ParamsFactory` 的覆盖键查询每属性只发生一次，后续轮次读缓存且返回值一致

#### Scenario: falsy 的解析值是有效缓存
- **WHEN** 某 Worker 的覆盖配置显式为 `0`（如 `phase: 0`），解析后被缓存
- **THEN** 后续解析直接得到 `0`，不会因真值判断而重查或回落到全局默认

#### Scenario: 重注册与复位使缓存失效
- **WHEN** 发生调度列表整体替换、同名 Worker 重新注册、或内核 `clear`
- **THEN** 相应 Worker（或全部）的缓存条目作废，下一次解析按新的参数配置重新求值
