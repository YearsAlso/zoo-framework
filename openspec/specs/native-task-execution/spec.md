# native-task-execution Specification

## Purpose
定义「Python 保留编排与生命周期、Rust 经显式适配层执行真实任务」的能力契约：语言无关的任务执行形状、原生扩展的可选性与显式失败、GIL 释放语义、单一结算与停机资源边界。

## Requirements

### Requirement: 系统 MUST 提供语言无关的原生任务执行契约

系统 SHALL 提供一个描述原生任务的执行契约，字段 MUST 覆盖：任务名与契约版本、输入格式与最大尺寸、输出格式、错误分类、能力查询（如支持原生内部并行/零拷贝等，首版声明为不支持）。契约 MUST NOT 暴露 PyO3 / Tokio / 其余原生绑定类型到内核。

#### Scenario: 契约字段完整且语言无关
- **WHEN** 按契约定义一个原生任务并读取其描述
- **THEN** 任务名、契约版本、输入/输出格式、错误分类与能力清单均可读取，且不含任何原生绑定类型

### Requirement: 原生扩展 MUST 为可选依赖且缺失时显式失败

未安装原生扩展时，框架的既有功能 MUST 全部可用。执行契约在扩展缺失、契约版本不匹配或能力不满足时 MUST 在执行前明确拒绝（raise 或返回显式错误），MUST NOT 静默回退到 Python 实现。原生扩展的 Python 下界 MUST 独立于主包声明：可选扩展 MUST NOT 抬高主包的安装门槛，两侧下界不一致时 MUST 在文档中写明各自的下界，且在主包支持的下界解释器上安装该扩展 MUST 以显式错误结束，MUST NOT 产生"装上但不可用"的状态。

#### Scenario: 未安装扩展时请求原生任务被明确拒绝

- **WHEN** 在未安装原生扩展的进程中请求执行某个原生任务
- **THEN** 收到显式错误，指明缺失的是扩展而非该任务名

#### Scenario: 未安装扩展时既有功能不受影响

- **WHEN** 未安装扩展时使用普通 Worker、事件管线与状态机
- **THEN** 全部行为与不引入本变更时一致

#### Scenario: 契约版本不匹配被明确拒绝

- **WHEN** 已安装扩展的契约版本高于/低于框架支持的版本且不兼容
- **THEN** 请求原生任务被明确拒绝，错误注明两侧版本

#### Scenario: 扩展的下界独立于主包

- **WHEN** 比较主包与原生扩展各自声明的 Python 下界
- **THEN** 主包的下界不因扩展的下界而抬高；两者不同时，文档中能查到各自的下界与理由

#### Scenario: 在主包下界解释器上安装扩展显式失败

- **WHEN** 在主包支持的下界解释器上尝试安装原生扩展
- **THEN** 安装以显式错误结束（解释器版本不满足扩展的声明），不产生"装上但不可用"的状态

### Requirement: NativeTaskWorker MUST 复用 Worker 生命周期与单一结算

NativeTaskWorker SHALL 继承既有 Worker 生命周期（属性字典承载配置、`is_loop` 为属性、hooks、`WorkerResult`），在 `_execute()` 内委托执行契约。其结果 MUST 只经既有单一结算点（`run_and_settle → settle`）投递，MUST NOT 适配器内额外投递。运行标识 MUST 由结算点按登记项盖章（复用 `run-identity`），适配器 MUST NOT 自行生成或丢弃 run_id/session_id。

#### Scenario: 原生任务成功时结果经单一结算点投递
- **WHEN** 一个原生任务执行成功
- **THEN** 恰好投递一次 WorkerResult（含原生输出、正确 worker 名与运行标识），且无第二次投递

#### Scenario: 原生任务报错时错误映射进结算收口
- **WHEN** 一个原生任务返回受控错误或 Rust 侧 panic（unwind）
- **THEN** 适配器把错误映射为异常，Worker 执行体把异常抛给结算收口（`settle(error=...)`），不投递成功空结果

#### Scenario: 原生长任务执行时控制线程可推进
- **WHEN** 一个原生任务执行体内不访问解释器地长跑
- **THEN** 同一进程中的 Python 控制层线程（调度轮、其他 Worker、事件管线）继续推进

### Requirement: 原生任务 MUST 支持超时观测与停机语义且不超过既有契约

原生任务的超时 MUST 按既有语义「只观测与熔断（标记不健康、停止派发），MUST NOT 声称线程/任务已终止」。停机后不再接收新任务；仍在执行的原生任务按既有的 `stop_semantics` 处理；原生长任务持有的资源 MUST 有显式归属与可观测状态，释放走显式生命周期钩子且幂等（MUST NOT 依赖 `__del__`）。

#### Scenario: 超时只熔断不声称终止
- **WHEN** 一个原生任务超过其派发截止期
- **THEN** 该 Worker 被熔断（不再参与下一轮派发）且上报不健康，但任务实际可能仍在执行；系统不报告「已终止」

#### Scenario: 停机后不再接收新任务
- **WHEN** 框架停机后再请求派发一个原生任务
- **THEN** 派发被拒绝或收不到结果；已登记的在飞状态按停机语义收口

#### Scenario: 资源释放幂等且有限等
- **WHEN** 对同一原生资源触发两次关闭，以及带总等待预算等待其释放
- **THEN** 第二次关闭为无副作用空操作，且总等待不超过声明的预算上限

### Requirement: 原生输入 MUST 明确所有权与生命周期边界

原生任务的首版输入以可确定所有权的数据（字节或简单值）承载。边界处一次性转换输入、执行体内保持原生数据、完成后一次性转换输出。释放 GIL 期间 MUST NOT 读取可能被其他线程修改的 Python 可变对象。零拷贝非本文默认承诺：仅当复制成本被证明显著时再评估，且必须定义持有者与释放时机。

#### Scenario: 输入进入执行体后被锁定
- **WHEN** 一个原生任务开始执行
- **THEN** 输入数据在边界一次性转入原生侧，后续 Python 侧对该输入对象的修改不影响正在执行的任务

#### Scenario: 高频复用的输入退出后仍可读
- **WHEN** 一段可复用的原生数据在任务结束后返回 Python 侧持有
- **THEN** 该数据的所有权与释放时机由显式约定描述；持续持有不导致意外释放或泄漏
