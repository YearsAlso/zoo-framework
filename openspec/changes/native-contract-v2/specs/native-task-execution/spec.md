# native-task-execution Delta Spec

## MODIFIED Requirements

### Requirement: 系统 MUST 提供语言无关的原生任务执行契约

系统 SHALL 提供一个描述原生任务的执行契约，字段 MUST 覆盖：任务名与契约版本、输入格式与最大尺寸、输出格式、错误分类、能力查询（如支持原生内部并行/零拷贝等，首版声明为不支持）。契约 MUST NOT 暴露 PyO3 / Tokio / 其余原生绑定类型到内核。

输出格式的取值集合 MUST 覆盖三态：`"bytes"`（不透明字节）、`"json"`（UTF-8 JSON 文本）、`"python"`（扩展在 FFI 边界构造并移交的纯 Python 数据对象）。声明 `"python"` 的任务，其输出对象图 MUST 只含语言无关的纯数据（None / bool / int / float / str / bytes / list / tuple / dict），MUST NOT 含原生绑定类型、框架对象、迭代器或 Rust 内存视图；该对象的所有权 MUST 在边界一次性转移给调用方，扩展 MUST NOT 在返回后继续持有或修改它。

#### Scenario: 契约字段完整且语言无关
- **WHEN** 按契约定义一个原生任务并读取其描述
- **THEN** 任务名、契约版本、输入/输出格式、错误分类与能力清单均可读取，且不含任何原生绑定类型

#### Scenario: python 输出以新构造的对象一次性移交所有权
- **WHEN** 一个声明 `output_format = "python"` 的任务执行成功
- **THEN** 框架收到的是新构造的纯 Python 数据对象（无需任何解码即可使用），且扩展侧不再持有或修改它

#### Scenario: 输出形状违约按输出解码失败族的语义被拒绝
- **WHEN** 一个声明 `output_format = "python"` 的任务返回了含原生包装类型、框架对象或迭代器的对象图
- **THEN** 执行以显式错误结束、错误指名违约的任务与「期望 / 实际」类型，且该错误归属既有三族中的输出解码失败语义（`NativeInvalidInput`），MUST NOT 被当作成功结果投递、MUST NOT 归入 panic 族

## ADDED Requirements

### Requirement: 契约主版本变更 MUST 显式拒绝版本不匹配的扩展

框架 SHALL 维护单一的原生执行契约主版本常量。扩展经 `contract_version()` 上报的版本与该常量不相等时，适配器 MUST 在执行任何任务之前显式拒绝，错误 MUST 同时给出两侧版本号；该拒绝 MUST NOT 被绕过、降级或静默回退到另一种输出形态。

契约主版本 MUST 只在四个入口的形状或语义发生不兼容变更时递增；新增任务、新增能力、新增一个输出格式取值 MUST NOT 单独触发递增。框架 MUST NOT 实现跨主版本的兼容执行（例如按配置在多个不兼容契约版本间选择，或为旧主版本保留一条转换路径）——版本不匹配 MUST 以拒绝而非降级收场。

扩展包与框架的契约版本 MUST 保持可判定的一致性：当主版本提升导致既有扩展会被拒绝时，框架声明的最小扩展版本范围 MUST 同步收紧，使依赖解析给出明确的「不满足」而非装入一个会被拒的扩展。

#### Scenario: v1 扩展在 v2 框架上被拒绝
- **WHEN** 一个上报 `contract_version() = 1` 的扩展在要求主版本 2 的框架上被请求执行任务
- **THEN** 请求在任务执行之前被拒绝，错误同时给出 1 与 2，且该扩展的执行体一次都没有被调用

#### Scenario: v2 扩展在 v1 框架上被拒绝
- **WHEN** 一个上报 `contract_version() = 2` 的扩展在只支持主版本 1 的框架上被请求执行任务
- **THEN** 请求在任务执行之前被拒绝，错误同时给出 2 与 1

#### Scenario: 新增任务或新增能力不递增契约主版本
- **WHEN** 扩展在不改变四个入口形状与语义的前提下新增一个任务或声明一个新能力
- **THEN** 契约主版本保持不变，既有扩展与框架的配对不受影响

#### Scenario: 主版本提升时扩展的版本范围同步收紧
- **WHEN** 契约主版本提升导致既有扩展版本会被拒绝
- **THEN** 框架声明的最小扩展版本范围随之提高，依赖解析不会为一个被拒的扩展版本报成功

### Requirement: execute 的返回形状 MUST 由任务契约的 output_format 决定

扩展入口 `execute(task, payload)` 的入参形状 MUST 保持 `(str, bytes)`。其返回值 MUST 由该任务契约声明的 `output_format` 决定：`"bytes"` 与 `"json"` 返回字节串（语义与契约 v1 相同），`"python"` 返回纯 Python 数据对象。

适配器 MUST 在输出边界按 `output_format` 分派：对 `"bytes"` / `"json"` 保持既有解码语义；对 `"python"` MUST NOT 做任何编解码，MUST 只做纯数据形状校验后原样移交。适配器 MUST NOT 对返回值做无条件的强制类型转换（例如无条件 `bytes(...)`）。

同一扩展内不同任务 MAY 声明不同的输出格式，且互不影响。框架、任务模板与契约校验器 MUST 对返回形状持有同一份可机械核对的声明。

#### Scenario: 同一扩展内不同任务声明不同输出格式
- **WHEN** 一个扩展注册了分别声明 `"json"` 与 `"python"` 的两个任务
- **THEN** 两个任务的输出各自按自己的声明被处理，互不影响

#### Scenario: 声明 python 却返回字节的执行被显式拒绝
- **WHEN** 一个声明 `output_format = "python"` 的任务返回了字节串
- **THEN** 执行以显式错误结束并指名该违约项，MUST NOT 把字节串当作合法的 Python 对象图移交

### Requirement: 契约输出的优化 MUST 以同一次运行内的四链路对照为验收证据

契约输出形态的优化（省去 JSON 编解码）MUST 以仓库既有的读数纪律验收：四链路对照（纯 Python 参考 / 既有原生库形态 / Rust 直调 / 适配链）MUST 在同一次运行内完成，预热分离、事前固定迭代数，且等价性前置检查不通过即中止。

验收 MUST 同时给出「沿用维护者已确认的 P50 / P99 门槛」与「新形态相对旧形态的增量」两组判据。MUST NOT 以「省去的编解码耗时」直接外推净收益——省下的编解码成本与新形态的构造开销 MUST 一起实测。

#### Scenario: 未达门槛时如实记 no-go 且不更换测量口径
- **WHEN** 新契约在门槛帧上未达到维护者确认的增量判据
- **THEN** 结论记为 no-go 并保留旧契约，MUST NOT 通过更换测量方法或跨运行拼接数字来凑门槛

#### Scenario: 工作包络外的小帧判定不因契约形态变化而改写
- **WHEN** 工作包络之外的小帧（小于 11 字节）在新契约下被测量
- **THEN** 该档仍按既有 no-go 结论处理，MUST NOT 因输出形态变化而被改判为 go
