# state-machine 规格变更（add-state-append-and-cas delta）

## ADDED Requirements

### Requirement: 集合键 MUST 支持逐条追加且不重写既有元素

状态层 SHALL 提供"向集合键逐条追加元素"的入口。追加 MUST 只新增元素，MUST NOT 重写或重排既有元素：追加后的读取 MUST 按追加顺序返回全部元素，既有元素的值与相对顺序 MUST 保持不变。目标键不存在时，追加 SHALL 以空集合为基自动创建；目标键当前值不是集合 / 序列时，追加 MUST 明确失败（显式错误），MUST NOT 静默覆盖其值。同一集合键上的并发追加 MUST NOT 丢更新（该"读取-追加-写回"MUST 对同一键原子）。追加 MUST NOT 幂等——重复调用产生多条元素；去重语义属调用方职责。既有 `set_state` 的整值替换语义 MUST NOT 被本条款改变。

#### Scenario: 逐条追加后按序读回全部元素
- **WHEN** 向同一集合键依次追加元素 A、B、C，随后读取该键
- **THEN** 读回结果按追加顺序为 A、B、C，元素个数为 3

#### Scenario: 追加不重写既有元素
- **WHEN** 先追加元素 A，再追加元素 B
- **THEN** 追加 B 后，A 的值与其在序列中的位置均未改变

#### Scenario: 对不存在的键追加自动以空集合为基
- **WHEN** 对一个此前不存在的键追加元素 X
- **THEN** 读取该键返回仅含 X 的集合，且键已被创建

#### Scenario: 对非集合值的键追加明确失败
- **WHEN** 对一个当前值为非集合（如整数）的键执行追加
- **THEN** 追加抛出显式错误，该键的原值 MUST NOT 被覆盖

#### Scenario: 并发追加不丢更新
- **WHEN** 多个线程对同一集合键并发各追加若干元素
- **THEN** 读回的元素总数为各线程追加数之和，无元素丢失

#### Scenario: 既有整值替换语义不受影响
- **WHEN** 对一个集合键使用既有的整值写入入口写入一个新集合
- **THEN** 该键的值被新集合整体替换，行为与合入前一致

### Requirement: 条件写 MUST 基于节点版本原子生效

状态层 SHALL 提供带"期望版本"的条件写入口：当且仅当目标节点当前版本严格等于期望版本时，写入 MUST 发生，且该节点版本 MUST 更新为严格大于写入前的值；否则写入 MUST NOT 发生，且 MUST 显式给出失败信号（调用方可据以重试），MUST NOT 静默成功。该"比较并写入"MUST 对同一节点原子：并发下使用相同期望版本的两次条件写，MUST NOT 都成功。节点的当前版本 MUST 可被读取，且每次成功写入后 MUST 严格递增，使其可用作乐观并发控制。条件写 MUST NOT 改变既有无条件写入口的契约——未提供期望版本时，写入行为 MUST 与合入前一致。比较 MUST 使用严格相等语义；节点不存在或无可比较版本时，条件写 MUST 明确失败而非退化成功。条件写失败（未写入）不改变节点状态，因此可安全重试，但"读取期望版本 → 条件写"整体 MUST NOT 被假定为幂等，调用方重试前 SHALL 重新读取版本。

#### Scenario: 版本匹配时条件写成功且版本递增
- **WHEN** 读取节点当前版本 v，以期望版本 v 执行条件写
- **THEN** 写入成功，读取该节点得到新值，且版本严格大于 v

#### Scenario: 版本不匹配时写入不发生
- **WHEN** 节点已被推进到版本 v2，以过期的期望版本 v1 执行条件写
- **THEN** 条件写给出失败信号，读取该节点得到的仍是 v2 对应的旧值

#### Scenario: 并发相同期望版本只有一个成功
- **WHEN** 两个线程以相同的期望版本并发对同一节点执行条件写
- **THEN** 恰好一个成功，另一个失败，节点值等于成功者的写入值

#### Scenario: 未提供期望版本时行为与合入前一致
- **WHEN** 使用既有无条件写入口写入一个节点
- **THEN** 写入无条件生效，行为与合入前一致

#### Scenario: 节点版本严格递增
- **WHEN** 对同一节点连续执行多次成功写入
- **THEN** 每次写入后的版本都严格大于上一次的版本
