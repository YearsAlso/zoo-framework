# 发布说明要点

本变更含两处**调用方可见的行为变更**，必须在提交信息中单列。

`release.yml` 的 GitHub Release 正文由 `git log --pretty=format:"- %s (%h)"` 生成，
因此下方内容 MUST 写入对应提交的 **commit message 正文**，否则下游看不到。

---

## BREAKING · `zfc --worker` 的产出目录改变

**此前**：`zfc --worker <name>` 总是把文件写入 `./workers/`。
判据是 `sys.argv[0].endswith("/src")`，而该条件对可执行入口（Windows 的 `zfc.exe`）、
模块方式、脚本方式**在所有平台上都不成立**——也就是说这条分支从未生效过。

**此后**：依据当前工作目录的实际结构判定——存在 `src/` 时写入 `./src/workers/`，
否则写入 `./workers/`。

**影响**：在脚手架项目根目录执行该命令的调用方，产出的文件位置会从 `./workers/`
变为 `./src/workers/`（这才是脚手架项目 `create_func` 约定的布局）。
在 `src/` 内执行或在非脚手架目录执行的调用方不受影响。

---

## BREAKING · `zfc --config` 被移除

该选项此前被命令行接受、但在命令实现体内**零引用**，即静默忽略。
现已移除；传入该选项会明确报错 `No such option`。

由于它此前不产生任何效果，移除不改变任何既有可用行为，只把"静默忽略"变为明确拒绝。

---

## 预期表现变化 · 非 UTF-8 控制台下的日志字形降级

**此前**：在非 UTF-8 控制台（例如 Windows 中文环境的 `cp936`）上，含 emoji 或部分
非 ASCII 字符的日志会触发 `UnicodeEncodeError`，被 `logging` 吞掉后**整行日志连同
时间戳一起消失**，只在 stderr 留下一段 `--- Logging error ---`。

**此后**：整行内容与时间戳**始终被写出**，无法用目标编码表示的字符降级为可还原的
转义序列（emoji 显示为形如 `\U0001f4e6` 的转义文本）。

**这是预期行为，不是回归**：日志的首要契约是"不丢行"，字形正确是次要的。

---

## 其他（非 BREAKING）

- **配置文件的编码**：读写统一为 UTF-8。此前依赖平台默认编码，导致同一份含非 ASCII
  的 `config.json` 在 Windows 上被读成乱码且**不报错**。读取路径对既有的非 UTF-8 文件
  提供回退，并在回退时输出告警指明该文件应迁移为 UTF-8
- **备份文件名**：时间戳精度由秒提升到微秒。此前同一秒内的多次备份会相互覆盖
  （实测 5 次备份只留下 1 个文件）。命名仍保持"字典序等于时间序"，新旧命名可共存
