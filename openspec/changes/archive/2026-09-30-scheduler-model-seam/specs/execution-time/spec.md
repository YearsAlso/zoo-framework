## Purpose

定义执行的时间语义：单调时间基准、由 Worker 逐个声明的周期与相位、跳过语义、按 Worker 观测的抖动、以及可分别施加于事件与派发的截止期。该能力使周期执行不再逐轮累积漂移，使抖动成为可验收的数字，并明确"超期只观测与熔断、不声称已终止"这一既有边界。

## ADDED Requirements

### Requirement: 时间计算 MUST 以单调时钟为基准

所有区间、期限、周期与抖动的计算 MUST 以单调时钟为基准。墙钟 MUST NOT 参与任何区间运算，仅可用于日志与展示。

#### Scenario: 墙钟被调整不影响期限判定
- **WHEN** 一次执行的期限判定过程中系统墙钟被向前或向后调整
- **THEN** 该期限的判定结论与墙钟调整前一致

#### Scenario: 抖动由单调时钟测得
- **WHEN** 查询某次周期触发的抖动
- **THEN** 该抖动由单调时钟测得，不随墙钟调整而改变

### Requirement: 周期与相位 MUST 由 Worker 逐个声明，且排期 MUST 不累积漂移

周期与相位 SHALL 是**每个 Worker 的声明**，而非进程或调度模型的属性——同一进程内 MUST 可以同时存在周期驱动的 Worker 与事件驱动的 Worker（设备场景里周期控制回路与事件驱动的报警处理器正是如此）。

周期与相位的来源优先级 MUST 为：Worker 自身声明的属性 → 按 Worker 名的配置覆盖 → 全局默认值。调度 MUST 以声明的周期**绝对序列**计算每次触发时刻，MUST NOT 以"上一轮执行结束时刻 + 周期"排期；因此单轮执行时长 MUST NOT 影响后续触发时刻。

未声明周期（或周期不为正）的 Worker SHALL 按事件驱动处理：每一轮调度都视为到点。

#### Scenario: 执行时长不改变后续触发时刻
- **WHEN** 周期为 T 的 Worker 某一轮执行耗时显著长于其他轮
- **THEN** 后续触发时刻仍由声明周期决定，不因该轮耗时被推后

#### Scenario: 相位被遵循
- **WHEN** Worker 声明了相位偏移
- **THEN** 首次触发相对基准时刻存在该偏移

#### Scenario: 多轮之间保持同一相位
- **WHEN** 声明了相位的 Worker 连续执行多轮
- **THEN** 各轮触发时刻相对理论时刻的偏移量保持在同一相位上，不逐轮累加

#### Scenario: 周期与事件驱动可在同一进程内并存
- **WHEN** 一个 Worker 声明了周期而另一个未声明，二者由同一调度器调度
- **THEN** 前者按周期序列触发、后者每轮都触发，互不影响

#### Scenario: 未声明周期时按事件驱动处理
- **WHEN** Worker 未声明周期
- **THEN** 它每一轮调度都被视为到点

### Requirement: 单轮超周期时 MUST 跳过错过的轮次并计数

当某一轮的执行时长超过声明周期、导致若干理论触发时刻已经过去时，调度 MUST **跳过**那些已错过的轮次，只在下一个未来时刻再次触发，MUST NOT 补跑积压轮次——补跑会在持续过载下自我放大。跳过次数 MUST 可查询。

#### Scenario: 过载后不补跑
- **WHEN** 某一轮的执行时长跨越了 k 个理论触发时刻
- **THEN** 该轮结束后只在下一个未来时刻触发一次，不补跑这 k 次

#### Scenario: 跳过次数可查询且与实际一致
- **WHEN** 发生过跳过
- **THEN** 跳过次数可被查询，且与实际错过的轮次数一致

#### Scenario: 未发生跳过时计数为零
- **WHEN** 每轮都在其周期内完成
- **THEN** 跳过次数为零

### Requirement: 抖动 MUST 按 Worker 观测且可查询

周期调度 MUST 按 Worker 记录每次触发的实际时刻与理论时刻之差，并 SHALL 提供至少三项：最近一次抖动、观测到的上界、样本数。MUST NOT 只提供平均值。

对**未声明周期**的 Worker，抖动 MUST 以显式的"不适用"标注返回，MUST NOT 以 0 代替——0 会被误读为"观测到零抖动"。

#### Scenario: 可查询最近抖动、上界与样本数
- **WHEN** 周期 Worker 执行若干轮后查询抖动
- **THEN** 最近一次抖动、观测到的最大抖动与样本数均可获得，且样本数与实际触发次数一致

#### Scenario: 抖动上界不因后续较小抖动而降低
- **WHEN** 先出现一次较大抖动、随后若干轮抖动较小
- **THEN** 抖动上界仍报告此前观测到的那个较大值

#### Scenario: 未声明周期的 Worker 抖动不适用
- **WHEN** 查询一个未声明周期的 Worker 的抖动
- **THEN** 返回"不适用"的显式标注，而非 0

### Requirement: 截止期 MUST 可分别施加于事件与派发，并在超过时熔断

期限 MUST 在两个**可独立施加**的位置生效，MUST NOT 假设二者之间存在因果链：

1. **事件侧**：事件 SHALL 可承载一个绝对截止期（单调时钟基准），其过期判定 MUST 依据该截止期。
2. **派发侧**：一次 Worker 派发 SHALL 可附带一个绝对截止期；执行超过该截止期时 MUST 观测到并熔断：记录超期、标记该 Worker 不健康、不再重派。

**边界说明**：调度器派发 Worker 与事件管道投递事件在本框架中是**两条不相交的路径**（事件投递给响应器，Worker 由调度器派发）。因此"截止期 MUST 随事件传递到最终执行的 Worker"这一因果链**不被本能力承诺**；建立该关联（事件触发 Worker 派发）属另一个能力。

#### Scenario: 事件按自身截止期判定过期
- **WHEN** 一个事件承载了绝对截止期且该时刻已过
- **THEN** 该事件被判定为过期，且判定依据是单调时钟而非墙钟

#### Scenario: 未承载截止期的事件不因期限被丢弃
- **WHEN** 一个事件未承载截止期
- **THEN** 它不因期限被判定过期

#### Scenario: 派发侧超过截止期被观测并熔断
- **WHEN** 一次 Worker 派发附带的截止期已过
- **THEN** 该次超期被记录、该 Worker 被标记不健康且不再被重派

#### Scenario: 熔断后不再无条件重派
- **WHEN** 一个 Worker 已因超过派发截止期被熔断
- **THEN** 调度不再重派它，除非调用方显式清除熔断标记

### Requirement: 超期 MUST NOT 被报告为已终止

系统 MUST NOT 声称已终止一个超期的执行。超期只产生"观测"与"熔断"两个结果；对执行体的终止 MUST NOT 被承诺，也 MUST NOT 在接口或文档中表述为已实现。

#### Scenario: 超期处理的表述只含观测与熔断
- **WHEN** 查阅超期处理的接口与文档表述
- **THEN** 只出现观测与熔断的表述，不出现已终止或已杀死执行体的表述

#### Scenario: 已熔断的执行体仍在运行时不阻塞调度
- **WHEN** 一个执行体因超期被熔断而其自身仍在运行
- **THEN** 系统既不等待它结束也不声称其已结束，且其他 Worker 的调度不受影响
