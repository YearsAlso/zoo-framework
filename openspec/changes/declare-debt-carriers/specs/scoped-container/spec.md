## Purpose（本变更新增条款）

进程级共享的"显式归类"从注释约定升格为登记表数据 + 扫描拦截；复位清单由登记表生成。

## ADDED Requirements

### Requirement: 进程级共享 MUST 在唯一登记表归类且由机制拦截遗漏

框架的每个进程级可变共享载体（模块级或类级的容器、注册面、配置面、单例、执行设施）MUST 在唯一登记表（`core/process_state.CARRIERS`）中拥有一条归类声明：分类、理由、以及是否随测试复位。判定 MUST 可由机制强制：一个覆盖全部框架模块的扫描 MUST 收集所有模块级/类级可变容器，任何既不能按对象身份、也不能按规范名匹配到登记表条目的载体 MUST 使测试失败。测试基座的复位清单 MUST 由登记表生成，MUST NOT 在 conftest 等处另行手抄。

#### Scenario: 新增载体未归类即测试失败
- **WHEN** 框架代码新增一个模块级或类级可变容器而未在登记表声明
- **THEN** 扫描测试失败并点名该载体，而不是等到出现跨用例串扰才被发现

#### Scenario: 复位清单只有一处真源
- **WHEN** 测试基座执行每个用例前后的复位
- **THEN** 复位动作全部来自登记表条目；登记表外的手工复位清单不存在

#### Scenario: 判为容器外的载体带理由在册
- **WHEN** 查询任一进程级载体的归类
- **THEN** 登记表给出分类与理由；被划为容器外（注册面/配置面/执行设施/常量）者 MUST NOT 被表述为"已由容器归类"，待收编者明确标注
