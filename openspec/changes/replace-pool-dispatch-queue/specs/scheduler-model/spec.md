## Purpose（本变更新增条款）

线程池模型的对外语义与容器实现解耦：换容器不得换行为。

## ADDED Requirements

### Requirement: 线程池模型的排队与停机语义 MUST 与容器实现解耦

`thread_pool` 模型对外的三项行为 MUST 与容器实现（Future 记账池或队列 + 固定线程）无关：**排队顺序**——同一线程被占满时，后提交的任务 MUST 按提交顺序（FIFO）被后续消费；**停机取消语义**（`stop_dispatch_cancel_queued`）——停机 MUST 丢弃尚未开始执行的排队任务、MUST NOT 中断已开始执行的任务；**异常观测**——执行单元逃逸出的异常（非 Worker 自身异常）MUST 被记录且承载线程 MUST 存活继续服务。池尺寸非法（`<= 0`）时启动 MUST 当场报错，MUST NOT 静默建出无法派发的工作池。

#### Scenario: 尺寸 1 的池按 FIFO 消费排队任务
- **WHEN** 唯一工作线程被先提交的任务占住，随后依序提交多个任务，再释放占用
- **THEN** 后提交的任务按提交顺序依次执行，不重排

#### Scenario: 停机丢弃未开始任务而不中断已开始任务
- **WHEN** 一个任务正在执行、另一任务仍在排队时调用停机
- **THEN** 已执行的任务跑完，排队任务不再执行；两者都不产生错误日志以外的副作用

#### Scenario: 逃逸异常留痕且线程存活
- **WHEN** 某任务的执行单元抛出 Worker 层之外的异常
- **THEN** 异常被记录，承载线程继续消费后续任务

#### Scenario: 非法池尺寸当场拒绝
- **WHEN** 以 `<= 0` 的生效尺寸启动线程池模型
- **THEN** 抛出 `ValueError` 并指明配置项，而非进入"已提交但永不执行"的状态
