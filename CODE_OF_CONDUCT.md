## 🇬🇧 English

### Our pledge

We want participating in Zoo Framework to be a harassment-free experience for everyone,
regardless of age, body size, visible or invisible disability, ethnicity, sex
characteristics, gender identity and expression, level of experience, education,
socio-economic status, nationality, personal appearance, race, caste, colour, religion, or
sexual identity and orientation.

### Expected behaviour

- Be direct about the code and courteous to the person.
- Assume the other person is acting in good faith; ask before concluding.
- Accept that reviewers may decline a change, and that a maintainer may disagree with you
  about scope. This project deliberately declines features — "no" is a design decision
  here, not a judgement about you.
- Give and receive criticism about the work, not the person.

### Unacceptable behaviour

- Harassment, insults, or personal attacks, public or private.
- Sexualised language or imagery, and unwelcome sexual attention.
- Trolling, deliberately inflammatory comments, and sustained disruption.
- Publishing someone's private information without explicit permission.
- Dismissing newcomers for asking questions. This framework's whole premise is that a
  wrong input should fail loudly — a question is the same mechanism, not an imposition.

### Scope

This applies in all project spaces (issues, pull requests, discussions in a review thread)
and whenever someone is representing the project in public.

### Reporting and enforcement

Report abuse to **mengxiang931015@live.com**, starting the subject line with
`[Code of Conduct]`. Reports are read by the maintainer only, and the reporter's identity is
not disclosed without their consent.

**This is a different route from security reporting.** Vulnerabilities must not come through
here: they go to the private channel in [SECURITY.md](SECURITY.md), which is a GitHub private
security advisory first and the same email second. Mixing the two routes loses a report.
Platform-level harassment (spam, impersonation, coordinated abuse) can additionally be
reported to GitHub directly through the **Report abuse** link on the relevant profile,
comment or repository — that route does not depend on this project's maintainer at all.

Responses, chosen to fit the incident:

1. **Private warning** — a written explanation of why the behaviour was inappropriate.
   Used for a first, non-severe incident.
2. **Temporary ban** — no interaction with the people involved for a set period. Used for
   repeated or more serious incidents.
3. **Permanent ban** — used for a pattern of violations, or a single severe one.

The maintainer recuses themselves if they are the subject of a report; there is currently no
second maintainer, so there is **no independent third party** who can receive a report about
the maintainer. In that case the report is acknowledged and the outcome is stated publicly
without disclosing the reporter.

<a name="中文"></a>
## 🇨🇳 中文

### 我们的承诺

我们希望参与 Zoo Framework 对每个人都是无骚扰的体验，不因年龄、体型、可见或不可见的
残障、族裔、性征、性别认同与表达、经验水平、教育程度、社会经济状况、国籍、外貌、种族、
种姓、肤色、宗教或性取向而有所区别。

### 期望的行为

- 对代码直接，对人客气。
- 默认对方出于善意；下结论之前先问。
- 接受评审人可能拒绝一个改动，也接受维护者可能在范围上与你意见不同。本项目会主动拒绝
  功能 —— 这里的「不」是设计决策，不是对你个人的评价。
- 只针对工作本身给出和接受批评。

### 不可接受的行为

- 骚扰、侮辱或人身攻击，公开或私下都算。
- 性化的语言或图像，以及不受欢迎的性关注。
- 引战、刻意挑衅的言论，以及持续扰乱讨论。
- 未经明确许可公开他人的私人信息。
- 因为新手提问而轻视对方。本框架的设计前提正是「错误输入应当大声失败」—— 提问是同一套
  机制，不是一种打扰。

### 适用范围

适用于所有项目空间（issue、PR、评审线程中的讨论），以及任何人在公开场合代表本项目时。

### 报告与执行

请将不当行为报告到 **mengxiang931015@live.com**，并在**邮件主题开头**加
`[Code of Conduct]`。报告仅由维护者本人阅读，未经报告者同意不披露其身份。

**这条路由与安全漏洞报送不同。** 漏洞**不要**走这里：它走 [SECURITY.md](SECURITY.md)
描述的私密渠道——优先 GitHub 私密安全通告，其次才是同一个邮箱。两条路由混在一起会丢报告。
平台层面的骚扰（垃圾信息、冒充身份、有组织的攻击）还可以直接向 GitHub 举报：在相关
账号、评论或仓库上使用 **Report abuse**（举报滥用）入口，那条路完全不依赖本项目的
维护者。

处理方式按情节选择：

1. **私下警告** —— 书面说明该行为为何不当。适用于首次、不严重的情况。
2. **临时封禁** —— 在规定期限内禁止与相关当事人互动。适用于重复发生或较严重的情况。
3. **永久封禁** —— 适用于长期反复违规，或单次严重违规。

如果报告的对象是维护者本人，维护者应回避；本项目目前没有第二位维护者，因此**不存在
独立的第三方**来受理针对维护者本人的报告。这种情况下的处理方式是：确认收到报告，
并在不披露报告者身份的前提下公开说明处理结果。
